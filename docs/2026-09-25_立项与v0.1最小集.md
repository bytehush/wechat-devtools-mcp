# 微信开发者工具 MCP：立项与 v0.1 最小集

状态: 已实现
取代: 无（本项目首篇记录）

## 缘起

用户（编程新手）希望给 AI agent 做一个微信开发者工具的 MCP server：agent 能代替人
操作开发者工具（打开项目、预览、上传），实现"用自然语言开发/调试小程序"的闭环。
经确认选定路线：**自己写、JavaScript、最小集起步**。

需求一句话：给 AI agent 一个能安全操控微信开发者工具的 MCP server（v0.1 先做四件事）。

## 替代方案及为何不选

| 方案 | 不选原因 |
|---|---|
| 官方现成 MCP | 查证（2026-09-25）官方未提供开箱即用的 MCP server，只有 CLI 与自动化接口 |
| 社区 weapp-devtools-mcp | 用户想自己学一遍；且第三方实现不可控 |
| TypeScript | 用户选择 JS：零构建步骤、每行可读，适合入门 |
| MCP over HTTP/SSE | stdio 由 agent 以子进程拉起即可，无需端口管理与安全暴露，最通用 |
| 直连 IDE HTTP API（9420 端口） | 端口号是动态的且需自己管理 IDE 生命周期；CLI 已封装好这些，v0.1 用 CLI 更稳 |
| spawn cli.bat | Windows 上 Node 直接 spawn .bat 会报 EINVAL，且经 cmd.exe 转发引号易错；改为用工具自带 node.exe 直接跑 cli.js |

## 实现

- `src/index.js`：MCP server（SDK 低层 `Server` API，只用 JSON Schema，少一层 zod 概念），
  注册 4 个工具：`open_project` / `check_login` / `preview` / `upload`。
  - **路径安全（两层）**：
    1. **目录白名单**（用户拍板采纳）：`WECHAT_DEVTOOLS_MCP_ALLOWED_ROOTS` 环境变量声明
       允许操作的项目根目录（分号分隔），未配置时默认只放行自带测试项目；白名单外的路径
       在探测存在性之前就拒绝。起因：Mimosa 提交前扫描连续三次拦截"任意项目路径 →
       path-traversal"，与工具按设计接受用户指定路径存在结构性冲突；与用户确认后选择
       白名单方案（替代方案：在 Mimosa 放行该规则 / 继续改代码碰运气）。这也是对
       "给 agent 用"的正确防御——即使 agent 被提示注入，工具也出不了白名单。
    2. **入口规范化 + qrOutput 收口**：`projectPath` 经 `path.resolve` 后全程复用规范值；
       `preview` 的 `qrOutput` 强制落在项目目录内（`assertInsideDir`）——这是本工具唯一的
       "写文件"入口。
- `src/cli.js`：`runCli()` 封装 `execFile(node.exe, [cli.js, ...参数])`。
  关键决策：
  - **参数数组 + `shell: false`**：agent 传来的路径等值只作为单个 argv 项到达 CLI，不经 shell 解释；
  - **stdin 走 `ignore`（EOF）**：CLI 首次调用会弹 `Enable IDE Service (y/N)` 交互提问，
    EOF 让它立刻走默认分支快速失败，避免挂到超时（实测教训：不处理会挂 120 秒无任何输出）；
  - **GBK 解码兜底**：CLI 输出混合 UTF-8/GBK，检测到 `\uFFFD` 时用 `TextDecoder("gbk")` 重解码；
  - **超时**：execFile 自带 `timeout` + SIGKILL（120s，preview/upload 180s）；
  - **报错翻译表**：服务端口关闭 / 未登录 / touristappid / 路径不存在 → 各给一条"下一步怎么做"。
- `src/config.js`：工具安装目录定位。优先级：环境变量 `WECHAT_DEVTOOLS_CLI` > 常见路径探测；
  校验标准是目录内同时存在 `node.exe` 和 `cli.js`。
- `test/smoke.mjs`：拉起 server 子进程，用换行分隔 JSON-RPC 走 MCP 握手 → tools/list →
  真实调用，含两条错误路径断言。
- `fixtures/demo-miniprogram/`：Hello World 测试小程序（官方 `touristappid` 游客 AppID）。

上传工具属对外动作：version 必填且校验 `x.y.z` 格式，描述必传可空，结果如实返回。

## 验证（本轮实际跑过的命令与输出）

1. 语法关：`node --check src/config.js src/cli.js src/index.js test/smoke.mjs` → `SYNTAX OK`
2. 冒烟：`npm run smoke` → **15 通过，0 失败**。其中真实链路：
   - `check_login` → `登录状态：已登录`（CLI 实际输出 `{"login":true}`）
   - `open_project`（fixtures 测试项目）→ 成功，IDE 中真实打开
   - 错误路径×3：白名单外目录（探测存在性之前拒绝）、白名单内不存在目录、touristappid 预览返回 AppID 提示
   - 安全路径：`qrOutput` 指向 `C:\Windows\Temp` 被拒，错误信息说明"必须位于项目目录内"
3. 反证关（三轮）：
   - 把 `EXPECTED_TOOLS` 临时加一个假名字 → 红（exit 1，断在 tools/list）；还原 → 绿（exit 0）
   - 临时注释掉 `assertInsideDir` 调用 → 红（12 通过 1 失败，断在 [7] 安全路径）；还原 → 绿
   - 临时禁用 `assertAllowedPath` 调用 → 红（14 通过 1 失败，断在 [3a] 白名单）；还原 → 绿（15/0）
4. 环境实测中的发现（都写进了 README 常见问题）：
   - 服务端口关闭时 CLI 卡在 `Enable IDE Service (y/N)` 交互，无输出地挂死；
   - **`taskkill /F` 强杀 IDE 会导致"服务端口开启"设置回落**（设置随正常退出才落盘），
     且 IDE 会自行重启进程，留下陈旧端口文件（`.ide`）→ CLI 连不上端口 → 所有命令超时；
     修复方式：杀干净全部 `wechatdevtools.exe` → 删除 `User Data\<hash>\Default\.ide` → 重新 `cli islogin` 拉起。

**未验证（待用户手验）**：preview 与 upload 的**成功路径**——需要真实小程序 AppID + 手机扫码，
本轮只有游客 AppID，只能验证到错误路径与前置检查。标注：已完成待验证。

## 接入 ZCode（已完成）

写入用户级配置 `~/.zcode/cli/config.json` → `mcp.servers.wechat-devtools`：
`node src/index.js` + `WECHAT_DEVTOOLS_MCP_ALLOWED_ROOTS=D:\A-Project-Search\ZCode`
（用户的各项目都在此目录下）。已用与生产配置完全相同的环境变量拉起 server 做真实调用验证：
`open_project` 成功在 IDE 中打开测试项目。新会话启动后 agent 即可调用这 4 个工具。
