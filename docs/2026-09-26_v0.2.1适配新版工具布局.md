# v0.2.1：适配新版开发者工具（无 node.exe 布局）

状态: 已实现
取代: 无（前篇 [2026-09-26_v0.2自动化操控.md](./2026-09-26_v0.2自动化操控.md) 的结论仍有效，本文只写增量）

## 缘起

用户反馈：新版开发者工具（2.02.2608070）**不再自带 node.exe**，MCP 的探测与调用
全部失效，开不了新项目。用户已在自己的项目（健身小程序）里用 `cli.bat` +
`miniprogram-automator` + CDP 脚本绕过并完成验证，修复方向写在
[其项目记录](../../健身小程序/docs/2026-09-26_立项与MVP.md)。本次按该方向修复 MCP 本体。

需求一句话：MCP 在无 node.exe 的新版工具上恢复全部能力，并用真实项目验证。

## 排查实录（三个关键事实）

1. **新版 CLI 机制**：cli.bat 改为 `ELECTRON_RUN_AS_NODE=1` + 挑选 >50MB 的主程序
   exe 充当 Node 运行时，CLI 入口迁至 `resources/app.asar.unpacked/js/common/cli/index.js`。
2. **`-e` 内联引导脚本不可行**：先按官方逐字复制（含 `require(e)`）被 Mimosa 判
   动态 require 拦截；改 `module.createRequire(e)(e)` 后实测失败——该运行时的
   `-e` 上下文里 `module` 不是完整模块对象。最终把引导脚本做成仓库内真实文件
   `src/cli-bootstrap.cjs`：文件上下文里 `require("node:module")` 是静态加载（过扫描），
   `createRequire(__filename)(entry)` 是官方 require(e) 的标准等价写法，实测可用。
3. **固定自动化端口会串会话**：两个项目窗口同开时，旧会话占着 9421，
   `cli auto --auto-port 9421` 表面成功（✔ auto），连接却落到旧项目窗口——
   表现为"导航到不存在的页面""get_page_info 返回别家数据"。
   修复：端口按**规范化项目路径哈希**确定（20000-39999，避开 Windows 动态端口段）。

另吸收用户记录的两个结论并落进代码：服务端口开关改配置文件无效（渲染进程
localStorage 启动时覆盖磁盘），正确姿势是 `--enable-service-port` 启动参数；
CLI 的 y/N 确认需要真 TTY——带上上述参数后提示不再出现，本就不该程序化回答它。

## 实现

- `src/config.js`：`probeLayout` 识别两种布局（旧 node.exe+cli.js / 新
  Electron-exe+app.asar.unpacked 入口），输出调用描述符
  `{ file, baseArgs, extraEnv }`；Electron 主程序按官方 cli.bat 的
  排除名单 + 50MB 阈值自动挑选。`getCliInvocation()` 供调用层使用。
- `src/cli-bootstrap.cjs`（新增）：文件版引导脚本，argv 重建与官方逐字等价。
- `src/cli.js`：`runCli` 按调用描述符执行（仍参数数组不经 shell；env 透传
  `ELECTRON_RUN_AS_NODE` 与官方同款的 `cwd`）；新增
  `runCliWithOptionalFlags(args, flags)`——失败输出点名了某个 flag（旧版 CLI
  不认识）时去掉重试一次，两次都失败以最后一次真实报错为准。
- `src/index.js` / `src/automation.js`：`open` 带 `--enable-service-port`，
  `auto` 带上述参数 + `--trust-project`（均走兼容回退）。
- **navigate 重写**：不再走 automator 的 `App.reLaunch` 命令（实测返回被吞成
  "Uncaught [object Object]"，tab 页尤甚），改为经 evaluate 调 appservice 的
  `wx.reLaunch`（天然支持 tabBar 页），校验 `errMsg === "reLaunch:ok"` 后读新路由。
- **automation_start 就绪探测**：代理附着可能早于 app 启动，轮询（≤20s）等首个
  页面出现；超时不阻塞会话建立，但在返回里如实提示，供 get_page_info 复查。

## 验证（本轮实际跑过的命令与输出）

1. 语法关：`node --check` 全部源码 → 通过；布局探测单元验证 → `kind = electron`
2. `islogin` 经新调用链 → `{"login":true}`（CLI 自动拉起 IDE，服务端口 37075）
3. 冒烟：`npm run smoke` → **26 通过，0 失败**（含真实 open/check_login/自动化全链路）
4. 反证关：给 electron 布局分支加 `COUNTER_PROOF` 环境开关，置 1 时冒烟红
   （exit 1，所有依赖 CLI 的断言失败——证明测试真实覆盖新调用链）；还原 → 绿（26/0）
5. **真实项目验证（健身小程序，tabBar + 真实页面结构）**：
   - `automation_start` → `应用就绪，当前页面：pages/record/record`
   - `navigate` 到 history / record（互跳）→ `get_page_info` 返回真实路径与 data
   - `screenshot` → 存入项目目录；`automation_stop` 正常断开
6. 诊断侧证（evaluate 直发）：`wx.switchTab`/`wx.reLaunch` 均 `:ok`，
   `getCurrentPages()` 路由随导航真实变化；evaluate 支持 Promise 返回值

**未验证**：preview/upload 成功路径仍需真实 AppID（健身小程序同为 touristappid）。
